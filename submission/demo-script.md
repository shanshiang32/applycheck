## 为什么用矢量生成而非录屏

- 文字与色块是矢量绘制，任何分辨率都清晰，不受录屏缩放/压缩影响。
- 每帧由 `render(t)` 确定性生成，同一数据必然产出同一视频，可复现、可审计。
- 数据直接取自 `evaluation/reviewed-20/results.json`、固定画像与平台用量，不手搓数字。
- 体积小（4.16 MB），便于随仓库分发与在线播放。

## 如何重新生成

```powershell
npm ci --ignore-scripts
node tools/vector-video/render.mjs --out media/applycheck-demo.mp4 --fps 30
```

源文件：[`tools/vector-video/frame.html`](../tools/vector-video/frame.html)（改文案/数据后重跑即可全部重生成）。
详见 [`tools/vector-video/README.md`](../tools/vector-video/README.md)。

## 校验记录（2026-10-26）

- `ffprobe`：h264 / 1920×1080 / yuv420p / 30fps / duration 68.000s / **2040 帧**（= 68×30，无丢帧）。
- 编码保真度：从 MP4 抽帧与直接渲染静帧比对，PSNR ≈ 36.8–38.8 dB（画面内容一致；若场景错位会降至 10–15 dB）。
- 逐帧文本可见性审计：12 个时间点抽查，各场景应出现的文字均可见、无错漏。
