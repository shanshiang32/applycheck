# 真实评估方案

本文件没有任何已测得的准确率或节省时间数据。不能将单元测试通过率当作招聘条件判断准确率。

## 样本与人工标注

优先对连续或固定规则选出的至少 20 个真实岗位做人工标注，避免只挑规则支持的简单案例。每条保存官网 URL、观察时间、原文、招聘项目、学历、专业、城市、毕业条件、实习时长、出勤条件和申请入口阶段。未知项显式标注 unknown。

入口阶段建议：仅发现控件 / 可进入后续页面 / 需要登录 / 明确关闭 / 无法核验。不能将 HTTP 200 或按钮存在当作可申请。

## 指标（务必保留分母）

1. 详情读取率 = 成功取得有效详情的岗位数 / 尝试岗位数。
2. 字段准确率 = 与人工标注一致的已自动提取字段数 / 已自动提取且有人工答案的字段数。缺失字段另算覆盖率。
3. 字段覆盖率 = 自动正确识别字段数 / 人工确认存在的目标字段数。
4. 硬条件误拒率 = 系统错误判断为不匹配的岗位数 / 人工判定符合已定义硬条件的岗位数。报告具体错误及置信边界。
5. 未知率 = 需要进一步复核的岗位数 / 有效详情数。不通过把 unknown 改成 pass 来降低未知率。
6. 时间：对相同任务分别记录人工核验与 Agent 核验加人工复核的总时间，计入登录、重试和验证。
7. 成本：记录实际浏览器时长、模型费用（若使用）、每条有效核验结果的成本；不填估造数字。
8. 证据完整率 = 同时有来源、时间、原文及可关联运行记录的结果数 / 报告结果数。

## 基线

- 基线 A：搜索/列表汇总，不进入详情。
- 基线 B：当前规则初筛。
- 完整流程：详情与申请阶段核验、复杂条件复核、变化记录。

保持任务、样本、条件和计时口径一致。初期小样本仅用于诊断，不宣称代表所有招聘站点。

## 变化验证

相隔至少一个实际工作时段重复采集同一批 URL。若没有自然变化，报告“未观察到变化”。可另用自建合成页面验证变化机制，但必须独立标为测试，不计入真实变化数量。
